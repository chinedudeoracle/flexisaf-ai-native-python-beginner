# Code Quality Checklist — Week 5

- [x] All functions are short and perform a single task.
- [x] Functions are named using snake_case.
- [x] Every function has a descriptive docstring.
- [x] Meaningful variable names are used (e.g., `length`, `width` instead of `x`, `y`).
- [x] Code is split across two files (module vs. execution) to separate logic from testing.
